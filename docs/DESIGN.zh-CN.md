# Nano-UB：UB 与 RoCEv2 的纯 SystemC 开源实现

**设计文档**
2026-06-24

> 本文档描述了华为统一总线（UB）传输层和事务层的洁净室（clean-room）SystemC 实现的架构、线缆格式和评估方法，同时包含一个与之对标的 RoCEv2 RC 基线。目标是进行并排对比，复现 UB 的架构主张——无连接状态伸缩、原生加载/存储延迟和分级排序——而无需依赖任何硬件描述语言编译器或 FPGA 工具链。

---

## 1. 背景框架

### 1.1 动机

华为统一总线（UB）规范 2.0.1 定义了一种无连接、事务解耦的 RDMA 类传输协议，它针对传统 RDMA 的两个结构性成本：每对队列对的 O(N·M) 连接状态爆炸，以及小操作的四次 PCIe 遍历延迟开销。UB 搭载在华为封闭的 Ascend 950 芯片中，同时存在一个开源的 FPGA 实现（OpenURMA，基于 OpenClickNP 构建），但目前尚不存在一个独立于工具链的纯仿真实现，让研究人员无需绑定特定 FPGA 编译器即可研究、修改和扩展。

Nano-UB 填补了这一空白：一个 **纯 SystemC** 实现的 UB 和 RoCEv2 RC，从一开始就设计为在相同的工作负载和评估基础设施上进行并排对比。

### 1.2 本项目是什么（以及不是什么）

| 是 | 不是 |
|----|------|
| UB 传输层/事务层的周期级 SystemC 模拟器 | 可综合的 RTL 设计 |
| 在相同仿真基础设施上的对标 RoCEv2 RC 基线 | 生产级 NIC 驱动栈 |
| 仅需 SystemC + C++17 的独立于工具链的参考实现 | OpenURMA FPGA 比特流的即插即用替代品 |
| 用于衡量 UB 与 RoCE 架构权衡的框架 | 完整的 UB 链路层或安全实现 |

### 1.3 三大架构支柱

本项目存在的目的是验证驱动 UB 和 OpenURMA 的同一组三大架构主张：

1. **传输/事务分离。** NIC 状态按 O(本地端点) + O(远程主机) 增长，而非 O(本地 × 远程)。这是约束 NIC 工作集大小的机制。

2. **原生加载/存储延迟。** 由于有界状态可放在芯片上，控制器位于 CPU 的片上总线而非 PCIe 之后，从而将小型同步操作的四次 PCIe 遍历压缩为一次片上总线穿越。

3. **分级排序。** 排序保证是按操作选择加入的，而非传输协议的固定属性。四种服务模式 × 三种执行标签 × 应用层 Fence × 两种完成排序模式，让应用仅在需要时才付出门控成本。

这三者形成一条依赖链：（1）通过约束状态为（2）创造条件，而（3）依赖于（1）所供应的每应用计数器。

## 2. 架构

### 2.1 元件图模型

NIC 被建模为一个由 FIFO 通道连接的 **处理元件** 有向图。每个元件是一个单一用途的处理块：它从其输入 FIFO 读取 flit，执行特定的协议功能，然后将 flit 写入其输出 FIFO。元件之间没有除 FIFO 中传递的数据之外的共享状态——数据流暴露了协议固有的并行性。

定义了两种拓扑：

- **UB 拓扑**：约 40 个元件，实现完整的传输/事务分离、四种服务模式、三种执行标签、加载/存储旁路路径和 Go-Back-N 重传。
- **RoCE 拓扑**：约 20 个元件，实现标准的 RC 队列对模型，包含每 QP 的 PSN 状态、BTH/RETH/AETH/AtomicETH 头部和 GBN 重传。

两种拓扑共享相同的线缆链路模型、相同的主机接口抽象和相同的评估框架——只有协议不同。

### 2.2 UB 拓扑

#### TX 路径（主机工作请求 → 线缆数据包）

```
主机工作请求
    │
    ▼
Doorbell ─── 验证输入 WR，剥离 flit 帧格式
    │
    ▼
Jetty 调度器 ─── 轮询 WR 分发，Fence 门控（§7.3.2.2）
    │
    ▼
排序跟踪器（发起端）─── ROI 模式下的 SO 门控（§7.3.3.2）
    │
    ▼
BTAH 构建器 ─── 打上事务头部（opcode、ODR、INI_RC_ID）
    │
    ▼
TPG 组 ─── 从池中选择一个 TP 通道（§6.4.3）
    │
    ▼
TP 通道 TX ─── 分配 PSN/TPMSN，维护每主机的传输状态
    │
    ▼
拥塞窗口 ─── LDCP 窗口（MVP 中仅为参考性，§6.6）
    │
    ▼
重传缓冲区 ─── 保存传输中副本用于 GoBackN 重传
    │
    ▼
RTPH 构建器 ─── 打上传输头部（PSN、TPOpcode、RSPST）
    │
    ▼
NTH 构建器 ─── 打上网络头部（24 位 CNA、NLP）
    │
    ▼
以太网封装 ─── 封装到以太网帧中（Ethertype 0x88B5）
    │
    ▼
线缆输出
```

对于 UNO 模式（不可靠）流量，TP 通道设置元数据标志，使流水线使用 UTPH 而非 RTPH，绕过 PSN 分配和重传缓冲区。

对于 §8.3 加载/存储（TP 旁路）流量，面向主机的入口被替换为加载/存储引擎，它直接将 flit 发送到 BTAH 构建器，NLP = TP_BYPASS，跳过整个传输层。

#### RX 路径（线缆数据包 → 主机完成）

```
线缆输入
    │
    ▼
以太网解封装 ─── 剥离以太网头部
    │
    ▼
NTH 解析器 ─── 按 NLP 路由：RTP（端口 1）vs UTP（端口 2）vs TP_BYPASS
    │
    ▼
RTPH 解析器 ─── 分离数据包与 ACK 包；拥塞回显
    │            在 FECN 上发出 CNP
    ▼
TP 通道 RX ─── 每主机接收器：PSN 窗口验证、ROL 融合
    │
    ▼
PSN 重排序 ─── 乱序重组缓冲区
    │
    ▼
BTAH 解析器 ─── 分离请求（端口 1）和响应（端口 2）
    │
    ▼
排序跟踪器（目标端）─── ROT 模式下的 SO 门控，TASSN 记录板（§7.3.3.3）
    │
    ▼
MR 表 ─── 内存区域查找和令牌 ID 验证（§8.2.4）
    │
    ▼
事务分发 ─── 按 opcode 分支：
    ├── 读取    → HBM 读取
    ├── 写入    → HBM 写入
    ├── 原子操作 → 原子 ALU（CAS/Swap/FAA/FSUB/FAND/FOR/FXOR）
    └── 发送    → Jetty 组 → Jetty 接收（投递到 JFR）
    │
    ▼
完成生成器 ─── 将请求翻转为 ATAH 响应
    │
    ▼
完成重排序 ─── 按序 vs 乱序完成缓冲区（§7.3.2.3）
    │
    ▼
TAACK 生成器 ─── 构建事务 ACK（ROI/ROT）；ROL 融合
    │               到 TPACK 中；UNO 被丢弃
    ▼
（通过 TX 合并路由回响应包）
```

到达发起端的响应（TPACK/TPNAK/TPSACK）被路由到完成流中，该流向上呈现主机可见的 CQE。

### 2.3 RoCE 拓扑

#### TX 路径

```
主机工作请求
    │
    ▼
Doorbell ─── 验证并转发 WR
    │
    ▼
QP TX ─── 每 QP 的 PSN 分配，源/目标 QPN 打标（§9.7.4）
    │         每个（本地 QP）有自己的 PSN 序列空间——这是
    │         标准的 RC 行为，也是 O(N·M) 伸缩问题的根源。
    ▼
BTH 构建器 ─── 打上标准 BTH 字段（tver、padcnt、opcode、pkey）
    │
    ▼
重传缓冲区 ─── 保存传输中 WQE 用于 GBN 重传
    │
    ▼
以太网封装 ─── 封装到 UDP/IPv4 + 以太网中（Ethertype 0x8915，UDP 4791）
    │
    ▼
线缆输出
```

#### RX 路径

```
线缆输入
    │
    ▼
以太网解封装 ─── 剥离 UDP/IPv4 + 以太网头部
    │
    ▼
QP RX ─── 每 QP 的 PSN 验证、排序、ACK 生成（§9.7.5）
    │
    ▼
BTH 解析器 ─── 提取 opcode，路由到分发器
    │
    ▼
分发器 ─── 按 opcode 分支：
    ├── RDMA 读取      → 内存读取
    ├── RDMA 写入      → 内存写入
    ├── ATOMIC_CAS/FAA → 原子 ALU
    ├── 发送           → 接收队列
    └── ACK/NAK        → QP TX ACK 处理
    │
    ▼
完成生成器 ─── 构建 CQE
    │
    ▼
ACK/NAK 生成器 ─── 构建 BTH+AETH 响应
    │
    ▼
（通过 TX 合并路由回）
```

### 2.4 图中的三大架构支柱

**支柱 1（状态分离）** 体现在按不同轴伸缩的独立表中：

| 表 | 伸缩依据 | UB | RoCE |
|-------|-------------|----|------|
| Jetty/端点表 | 本地应用数 | 每应用 1 个 | — |
| TP 通道 / QP 表 | 远程主机数 | 每主机 1 个 | 每对端 1 个 |
| MR 表 | 注册段数 | 每段 1 个 | 每段 1 个 |

由于 UB 将 Jetty 表（每应用）与 TP 通道表（每主机）解耦，总 NIC 状态为 O(本地端点 + 远程主机)。RoCE 将两个身份融合到单个 QP 对象中，因此状态为 O(本地 × 远程)。

**支柱 2（加载/存储延迟）** 由加载/存储引擎入口实现，该入口用一条直接的片上总线到 BTAH 路径替代了 doorbell/Jetty/OrderTracker/TPChannel 链。UB TX 路径在此模式下约需 ~8 个周期完成，而完整的 URMA 异步路径约需 ~25 个周期。

**支柱 3（分级排序）** 分布在各个门控元件中：Jetty 调度器（Fence）、排序跟踪器发起端（ROI）、排序跟踪器目标端（ROT）、TP 通道 RX（ROL 融合）和完成重排序（完成顺序）。每个对应 §7.3 表面的一个轴。

### 2.5 主机接口抽象

两种拓扑暴露统一的主机接口：

```
wr_in      →  主机提交工作请求 flit
cqe_out    ←  NIC 发出完成事件 flit
wire_tx    →  向网络链路发出的 flit
wire_rx    ←  从网络链路到达的 flit
```

UB 拓扑额外暴露一个用于 §8.3 操作的加载/存储端口，完全绕过 WR/CQE 机制——CPU 的内存请求直接进入加载/存储引擎，响应作为内存读取结果返回。

### 2.6 线缆链路模型

两个 NIC 实例通过一个 EtherLink 模型连接，该模型引入可配置的延迟、抖动和可选丢包：

```
NIC A          EtherLink           NIC B
wire_tx ────┬───────────┬──── wire_rx
            │  延迟 τ   │
wire_rx ←───┴───────────┴──── wire_tx
```

该链路模型独立于协议——同一链路可连接 UB NIC、RoCE NIC 或混合协议对。

## 3. 线缆格式

### 3.1 UB 线缆格式

UB 数据包封装在标准以太网帧中。每个数据包的线缆布局如下：

```
+------------+------------+------------+------------+
| 以太网头部 | NTH        | TPH        | TAH        |
| 14 B       | 12 B       | 16 B       | 16 B       |
+------------+------------+------------+------------+
| 扩展 TAH   | 负载（可变长度）                      |
+------------+--------------------------------------+
```

**以太网头部**（14 B）：dst_mac（6）| src_mac（6）| ethertype（2）。Ethertype = 0x88B5（本地实验用）。

**NTH —— 网络传输头部**（§5.2.2，12 B）：携带 24 位 CNA 网络层寻址。关键字段：

```
字节 0:       RT[1:0] | 保留[5:0]
字节 1-3:     SCNA[23:0]       — 源 CNA
字节 4-6:     DCNA[23:0]       — 目标 CNA
字节 7-8:     CCI[15:0]        — 拥塞控制标识符
字节 9:       LBF[7:0]         — 负载均衡字段
字节 10:      SL[3:0] | NLP[2:0] | mgmt[1]
字节 11:      保留
```

NLP 值：
- 0x010 = RTPH 后接（可靠传输）
- 0x011 = UTPH 后接（不可靠传输，OpenURMA 约定）
- 0x001 = TP 旁路（§8.3 加载/存储，无传输头部）

**RTPH —— 可靠 TP 头部**（§6.2.1，16 B）：

```
字节 0:       TPOpcode[7:0]
字节 1:       TPVer[1:0] | Padding[1:0] | NLP[3:0]
字节 2-4:     SrcTPN[23:0]
字节 5-7:     DstTPN[23:0]
字节 8:       A[1] | F[1] | 保留[5:0]
字节 9-11:    PSN[23:0]           — 包序列号
字节 12:      RSPST[2:0] | RSPINFO[4:0]
字节 13-15:   TPMSN[23:0]         — 传输消息序列号
```

TPOpcode 值：0x00 = UTP，0x01 = RTP 数据，0x02 = TPACK/TPNAK，0x03 = TPACK-CC，0x05 = TPSACK，0x06 = TPSACK-CC，0x08 = CNP。bit 7 标记事务的最后一个包。

**UTPH —— 不可靠 TP 头部**（§6.2.1，16 B）：最小头部，TPOpcode[0]=0，无 PSN 或重传字段。

**BTAH —— 基本事务头部**（§7.2.1，16 B）：

```
字节 0:       TAOpcode[7:0]
字节 1:       TAver[1:0] | EE_bits[1:0] | TV_EN | Poison | Target_Hint | UD_Flag
字节 2-3:     INI_TASSN[15:0]     — 事务序列号
字节 4:       No_TAACK | ODR[2:0] | MT_EN | FCE | Retry | Alloc
字节 5:       E_bit | INI_RC_Type[1:0] | 保留
字节 8-10:    INI_RC_ID[19:0]     — 发起端资源标识符
```

TAOpcode 值覆盖 18 种事务类型：Send（0x00）、Write（0x03）、Read（0x06）、全部八种原子操作码（0x07-0x0F）、TAACK（0x11）、读取响应（0x12）、原子响应（0x13）和管理操作码。

ODR[1:0] 编码执行顺序标签（00 = NO，01 = RO，10 = SO）。ODR[2] 选择按序完成通知。

**MAETAH —— 内存地址扩展 TAH**（§7.2.3，16 B）：为读/写/原子操作携带 64 位地址、20 位令牌 ID 和 32 位长度。

**ATAH —— ACK 事务头部**（§7.2.2，16 B）：响应头部，镜像 BTAH 字段，带有 RSPST/RSPINFO 状态码。

### 3.2 RoCE 线缆格式

RoCEv2 数据包封装在 UDP/IPv4 之上的以太网中（IBTA §9.3）。

```
+------------+----------+----------+------------+------------+
| 以太网头部 | IPv4     | UDP      | BTH        | RETH/AETH/ |
| 14 B       | 20 B     | 8 B      | 12 B       | AtomicETH  |
+------------+----------+----------+------------+------------+
| 负载（可变长度）                                          |
+----------------------------------------------------------+
```

Ethertype = 0x8915，UDP 目标端口 = 4791。

**BTH —— 基本传输头部**（12 B）：

```
字节 0-1:    Opcode[7:0] | TVer[3:0] | PadCnt[1:0] | SE | M | 保留
字节 2-3:    PKey[15:0]
字节 4-7:    DestQP[23:0] | A | 保留
字节 8-11:   PSN[23:0] | 保留
```

RC opcode 包括：SEND_ONLY（0x04）、RDMA_WRITE_ONLY（0x0A）、RDMA_READ_REQUEST（0x0C）、RDMA_READ_RESPONSE_ONLY（0x10）、ACKNOWLEDGE（0x11）、COMPARE_SWAP（0x13）、FETCH_ADD（0x14）。

**RETH —— RDMA 扩展传输头部**（16 B）：虚拟地址（8 B）、rkey（4 B）、DMA 长度（4 B）。出现在 RDMA WRITE 和 READ 请求中。

**AETH —— ACK 扩展传输头部**（4 B）：一个综合征字节，指示 ACK（0x00）、RNR-NAK（0x20）或各种 NAK 原因（0x60-0x63），后跟 3 个保留字节。

**AtomicETH**（28 B）：虚拟地址（8 B）、rkey（4 B）、交换/加法操作数（8 B）、比较操作数（8 B）。

### 3.3 内部 flit 格式

在模拟器内部，每个数据包表示为一个固定大小的元数据记录，以紧凑的位打包布局携带解析后的头字段。线缆字节与内部元数据之间的转换由拓扑边界处的以太网封装/解封装元件负责。

元数据记录为 64 字节，组织为四个 64 位通道：

| 通道 | UB 内容 | RoCE 内容 |
|------|-----------|-------------|
| 0 | NTH 摘要（DCNA、SCNA、NLP、valid） | BTH 摘要（opcode、pkey、dest_qp） |
| 1 | RTPH 字段（TPOpcode、PSN、TPMSN） | PSN、syndrome、flags |
| 2 | 标志（服务模式、响应、A/F） | 源 QP、rkey |
| 3 | BTAH 字段（TAOpcode、TASSN、ODR、RC_ID） | Cookies、内部路由 |

对于携带地址、长度、令牌或原子操作数数据的操作，后跟第二个"扩展"记录。

## 4. 评估方法

### 4.1 对比：UB vs RoCE

每个实验运行两次——一次在 UB 拓扑上，一次在 RoCE 拓扑上——使用相同的工作负载参数。唯一变量是协议。这镜像了 OpenURMA 的评估策略。

### 4.2 测量维度

**支柱 1 —— 状态伸缩：**

NIC 驻留状态测量为两个表中每连接上下文的总和：

```
State(N, M) = Σ(元件状态) × cardinality(元件, N, M)
```

| 元件 | UB 基数 | RoCE 基数 |
|---------|---------------|------------------|
| TP 通道 / QP | M（远程主机数） | N × M（本地 × 远程） |
| Jetty / 端点 | N（本地应用数） | N × M（融合到 QP 中） |
| MR 段 | 每注册 | 每注册 |

对于 N = M = 1024 的全互联场景，比率应接近 ~O(N·M)/O(N+M) ≈ 4855×。

**支柱 2 —— 端到端延迟：**

每个操作的路径分解为若干段：

| 段 | UB 加载/存储 | UB URMA | RoCE |
|---------|--------------|---------|------|
| 主机提交 | 0（ISA 加载/存储指令） | 内存总线遍历 | PCIe MMIO + DMA |
| NIC TX | ~8 周期 | ~25 周期 | ~9 周期 |
| 线缆 | 可配置延迟 | 可配置延迟 | 可配置延迟 |
| NIC RX + 远端内存 | ~8 周期 | ~25 周期 | ~9 周期 + PCIe |
| 完成 | 0（直接返回） | 内存总线 + CQE 轮询 | PCIe DMA CQE + 主机轮询 |

核心测量指标：200 MHz NIC 时钟假设下，64 字节远端读取，比较 UB 加载/存储延迟与 RoCE RDMA READ 延迟。

**支柱 3 —— 分级排序：**

四个实验探测每个排序轴：
1. ROI：SO 在同一个发起端上等待未完成的 RO
2. ROT：目标端延迟 SO 直到缺失的 TASSN 到达
3. ROL：TPACK 融合 TAACK，节省一个线缆 flit
4. UNO：不可靠模式绕过所有排序状态

交叉实验：同一 Jetty 上混合 NO/RO/SO 标签，验证只有 SO 标签的操作付出门控延迟。

### 4.3 工作负载

| 工作负载 | 测量内容 | 涉及的协议栈 |
|----------|---------|-------------|
| Ping-pong 延迟 | 最小操作延迟 | 两者 |
| 批量读/写 | 吞吐量 vs 负载大小 | 两者 |
| Send/recv | 双端消息传递开销 | 两者 |
| 混合排序 | NO/RO/SO 交错成本 | 仅 UB |
| 状态扫描 | 延迟 vs 活跃连接数 | 两者 |
| 丢包恢复 | 注入丢包下的有效吞吐量 | 两者 |
| 多对一扇出 | 目标端分发开销（Jetty 组 vs CPU） | 两者 |

### 4.4 对 OpenURMA 的验证

对于 OpenURMA 已公布的数据（500 ns 加载/存储，2236 ns RoCE READ，4.47× 比率，4855× 状态缩减），Nano-UB 的结果应在相同配置下落在 ±10% 以内。差异将被调查并记录——它们可能揭示真实的建模差异或错误。

### 4.5 确定性

所有随机化实验（泊松到达过程、链路抖动、丢包注入）都设置随机数种子，因此重复运行产生相同的结果。

## 5. 范围

### 5.1 包含范围

- UB 传输层：带 PSN/GoBackN 的 RTP、用于 UNO 模式的 UTP、简化的 CETPH 回显
- UB 事务层：BTAH/ATAH、全部 18 种操作码、全部四种服务模式（ROI/ROT/ROL/UNO）、全部三种执行顺序标签（NO/RO/SO）、应用层 Fence、两种完成排序模式
- UB §8.3 带 TP 旁路的加载/存储
- UB §7.4.2.3 原子操作套件：CAS、Swap、Store、Load、FAA、FSUB、FAND、FOR、FXOR
- RoCEv2 RC：SEND、RDMA WRITE、RDMA READ、COMPARE_SWAP、FETCH_ADD、带 GBN 重传的 ACK/NAK
- RoCEv2 DCQCN 拥塞控制（基于 ECN）
- 并排对比框架，使用相同的工作负载

### 5.2 不包含范围

- UB 物理/链路层（数据包在建模的 EtherLink 上运行，而非真实的收发器）
- 选择性重传引擎（仅 GoBackN）
- 超出单通道的 TPG 多路径负载均衡
- 安全分区、虚拟化、设备管理
- 真实硬件上的 C-AQM 拥塞控制（仅模拟交换机）
- RoCEv2 XRC、UD 或 DCT 传输模式
- 真实的 PCIe 或以太网硬件接口
