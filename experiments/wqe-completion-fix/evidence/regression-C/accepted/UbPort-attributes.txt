    --ns3::UbPort::PacketRateBurstSizeFlits=[0]
        Spec PACKET_BURST_SIZE (Table 4-9, Flit 4 bits 31:16, 16 bits): "Maximum number of burst flits supported by the peer receive buffer, in flits." Used by DYNAMIC only, and unlike the other dynamic parameters it is a plain field value rather than an invented default: the specification does not say whether 0 is legal, and this port reads 0 as "no burst allowance", so any positive deficit triggers padding. A peer whose buffer does absorb a burst has to be described explicitly.
    --ns3::UbPort::PacketRateControl=[NONE]
        Data link layer packet rate control mode (NONE, STATIC, DYNAMIC), UB Base Spec 2.1 §4.7. The sender fills No_Operation Blocks after small DLLDPs so the SOP-to-SOP interval between consecutive DLLDPs meets PACKET_MIN_INTERVAL, lowering the packet reception rate required of the peer receiver. DYNAMIC implements the §4.7.3.2 deficit counters directly. STATIC implements §4.7.3.1 per DLLDP instead of tracking the previous SOP: every DLLDP is padded against its own PACKET_MIN_INTERVAL, which agrees with the spec for back-to-back DLLDPs and is the more conservative reading after an idle period. DYNAMIC additionally needs the PacketRateAverage*/PacketRateDevice*/PacketRateBurst* parameters, which carry no defaults: §4.7.1 takes them from the peer receiver's Init Block, and the Table 4-9 note says "It is not allowed to send only part of the initialization parameters", so a partly configured DYNAMIC port aborts instead of assuming values. The parameters describe the peer receiver's capability and constrain this port's egress direction only; the two link directions are configured independently. Per §4.7.1 the mode is what the peer receiver advertised through the Init Block, so setting it here describes the peer, not this port. NONE is a simulator default rather than a specification-defined state: Table 4-9 encodes PACKET_RATE_CONTROL_MODE as a single bit with no disabled value.

Used by DYNAMIC only. No default: §4.7.1 takes it from the peer receiver's Init Block, and the Table 4-9 note forbids sending only part of the initialization parameters.
