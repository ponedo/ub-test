# Dynamic UB multicast: design alternatives and gates

Status: documentation-only proposal, not implemented, not simulated. No measured speedup, control-plane latency, or reliable group completion is claimed.

## Existing implementation constraints motivating the design

- Switch routing is one-output: `src/unified-bus/model/ub-switch.cc`, `UbSwitch::ForwardDataPacket`, lines 973–1005; `SendPacket` 1344–1346 dispatches to `ForwardDataPacketAfterAdmission` 449–478, accounting input bytes and enqueuing to one output/VL/input VOQ after ingress processing latency.
- `src/unified-bus/model/ub-switch-allocator.cc` lines 652–710 checks egress capacity, consumes downstream credit and returns upstream credit as one packet advances. `src/unified-bus/model/protocol/ub-cbfc.cc` 147–166 has recovery-oriented upstream-credit suppression, not a multicast ownership contract. Repeating SendPacket for three clones must not produce three upstream returns for one received packet.
- `src/unified-bus/model/ub-transport-channel-manager.cc`, `ResolveInboundTp`, 238–299 validates peer TPN, source/destination addresses and priority. Copying a B-addressed packet unchanged to C and D does not make those legitimate receivers.
- `src/unified-bus/model/protocol/ub-function.cc`, `CanAcceptWqe`, 1058–1072 enforces a bound Jetty's single destination; segmentation 1290–1318 copies one destination. Unbound mode relaxes that binding, not the packet/operation's target cardinality.
- `src/unified-bus/model/protocol/ub-transaction.h` 618–645 keys operations by Jetty/WQE and segments by SSN, with no recipient dimension. `ub-transaction.cc` 2114–2177 validates a response's reversed addresses, correlation, opcode and payload; `RecordSegmentSuccess` 1859–1918 retires one segment, not an all-recipient set.
- `src/unified-bus/model/protocol/ub-transport.cc` 1689–1714 advances one `sndUna`; 1732–1763 retires segments below that ACK state. `ub-retrans.cc` 1201–1225 decrements a retry count, asserts positive and reschedules; this is not a group-level terminal failure contract.

## Shared proposal contract

Define one frozen operation membership M for `(source, operation_id, expert_id, weight_version, layer, microbatch, membership_epoch)`. Expert ID alone is unsafe because physical replica slots are reused. Each receiver mapping must include rank/node, endpoint/Jetty or target-context identity, target buffer/offset and content version. Equal bytes at different target addresses are still distinct target execution contexts. Empty M completes by explicit no-op policy; singleton M uses unicast; source-local membership avoids network transmission but still satisfies local completion explicitly.

Freeze M before the first payload packet. New placement affects only a subsequent operation/epoch; it must neither remove an old receiver from an in-flight completion mask nor add a new receiver retroactively. Use immutable tree/group versions until all associated payload, ACK, retry and failure cleanup is quiescent. Prevent stale IDs from aliasing after reuse. Stop or fail explicitly if a target is removed; do not silently redefine success.

For multi-switch Clos or mesh, install a directed, source-rooted acyclic tree, not a collection of independent ECMP choices. At each branch split destination membership into disjoint child subsets, suppress arrival-link reflection and duplicates, retain valid next hops for each child, and define TTL/hop-limit plus topology version. Tree failover requires an explicit new version or a frozen-route failure outcome. A one-switch output-port mask does not establish arbitrary-topology multicast.

## A / B / C comparison (all proposed)

| Option | Data-plane state and bytes | Dynamic placement fit | Main costs and risks | Recommendation |
|---|---|---|---|---|
| A: preconfigured GroupID | Packet carries group ID + version; switches hold `(source,group,version)->child ports/subsets`. | Good for stable or cached recurring exact replica sets; each new subset needs an existing entry or a fallback. One static group per expert is incorrect when replicas change. Enumerating all subsets is exponential. | Table capacity, cache misses, version lifetime, membership activation and cleanup; no free runtime reprogramming. | Small fixed-group network PoC and best-case comparison. Label static membership; do not generalize to arbitrary per-layer plans. |
| B: destination bitmap/list | Packet carries intended receivers (bitmap about ceil(N/8) bytes, or k address/ID entries) plus operation/version fields; each switch splits/prunes by child. | Direct representation of volatile sparse groups without per-group switch install. | N-bit headers for dense namespace, k-entry list overhead, MTU/segmentation effects, branch parsing and tree selection, address mapping and endpoint-context reconstruction. | Strong dynamic baseline; sweep bitmap versus sparse list and fanout. A metadata-only implementation is an oracle, not measured wire-realistic multicast. |
| C: control-plane install | After plan readiness, compute/install versioned tree and endpoint contexts; packets carry compact GroupID/version after an activation barrier. | Can support arbitrary groups, with explicit critical-path setup. | Plan-to-tree compilation, communication/install time, partial install, table capacity, barrier/ACK overhead, teardown and in-flight retention. | Realistic dynamic candidate only after control-plane model specified; expose costs as unmeasured parameters, never assume zero as production behavior. |

Hybrid cache-hit A/cache-miss C or B is a later proposal, not baseline capability. All options still require per-target identity and reliable completion design; GroupID alone cannot fix the unicast TP model.

### Charge actual simulated bytes

`src/network/model/packet.h:849–852` returns only `m_buffer.GetSize()`. `src/network/model/packet.cc:257–265` (`AddHeader`) expands that buffer and serializes a header; `AddPacketTag` at 949–953 changes the tag list only. `src/unified-bus/model/ub-port.cc:648–649,805,842,850,863` uses `Packet::GetSize()` for flit/rate/serialization or byte accounting. Therefore multicast membership solely in `PacketTag` is uncharged on these simulated links even if host/distributed packet serialization can preserve tags. Put wire fields in an ns-3 Header and update MTU/segmentation parsing, or separately add explicit modeled bytes everywhere the link/queue/credit model uses size. Keep instrumentation tags separate and label any zero-byte oracle experiment.

### Charge dynamic control-plane time honestly

Inputs/parameters, not measurements: `T_map`, `T_tree`, `T_install`, `T_barrier`, `T_retire`, control-message sizes, table capacity, lookup/branch delay, replication service rate and copy/buffer cost. Host Python wall-clock preprocessing is not simulated network latency. A scheduled zero-time install is an idealized lower bound. Record `plan_ready`, `mapping_ready`, `install_start`, `install_complete`, `payload_start`, `all_targets_complete`, `state_retired`. In a serial model, total exposed time includes mapping + tree + install + barrier + data completion; if overlapped, specify a dependency DAG and use its critical path rather than simply summing or silently hiding time. Break-even requires measured or swept data-plane savings to exceed exposed setup and any added header/reliability overhead; no numeric speedup follows from this audit.

## PoC 1: network replication only

Question: can one injected payload reach exactly its intended destinations while consuming real per-link, per-queue and per-credit resources? This does not prove reliable URMA/RDMA or all-target CQE completion.

Start one source, one switch, three sinks, A fixed group; use explicit sink instrumentation rather than claiming unchanged destination-specific TP accepts all copies. Add two-level branching only after the first topology passes. Introduce a serialized test multicast header or explicitly label free metadata as an oracle. Define branch admission policy: either reserve all required egress/VOQ resources atomically, or retain a pending-output mask so each admitted child is sent once and blocked children retry locally. Avoid partial dispatch followed by full re-dispatch duplicates. Specify one ingress owner/reference counter and exactly one upstream-credit return, with per-egress downstream credit for every emitted copy. Choose physical per-copy buffers or shared payload plus per-output descriptors and charge the chosen model consistently. Input CBFC grants capacity for one arrival, while eager fanout may reserve N packet buffers: a separate replication pool/reservation/headroom contract is required even when upstream credit returns only once. Shared payload/pending-mask accounting requires QueueManager changes; ordinary triple SendPacket does not supply it. Packet::Copy preserves UID/tags and peer identity (packet.cc:120–150), so copies need explicit branch/lifecycle identity. CBFC removes inbound piggyback data before forwarding (ub-cbfc.cc:455–486), and each output attaches its own (427–451). Zero-delay Packet::Copy is only a chosen unlimited-replicator model, not an ASIC latency estimate.

Proposed validation matrix: fanout 0/1/3; one blocked output; mixed output link rates; tiny ingress/egress buffers; duplicate input; unreachable child; multi-switch shared-prefix tree; membership update during flight; stale group/version; deterministic branch drop. Assert no extra destination, no duplicate child transmission absent explicit retry, no queue/credit underflow/overflow, no deadlock, exactly-once input release, and full byte reconciliation. For equal payload B and three recipients, source uplink payload is B in the multicast proposal versus 3B in unicast; each leaf egress still carries B. This is a topology-specific byte identity, not a latency result. Include headers, control and retry bytes separately.

Go only if packet identities, egress sets, bytes and conservation invariants reconcile for every case. No-Go if the only evidence is three SendPacket calls, three copies at sinks, tag-only membership, or apparent throughput without accounting.

## PoC 2: reliable multi-target operation completion

Question: does the source declare one logical success only after every frozen member has completed the required target-side operation, with correct failures and retries?

Stage 2a semantic reference: issue independent ordinary unicast child WQEs per recipient and aggregate their terminal outcomes in a new logical parent. This reuses peer-specific TP state and supplies a correctness oracle. It DOES NOT save source-link data bytes or demonstrate hardware multicast.

Stage 2b shared-payload design: new multicast operation identity plus explicit per-recipient target execution metadata; keep per-target sequence/ACK window, segment status, retry budget and terminal outcome, and deduplicate by `(operation,epoch,target,segment)`. The receiver must validate correct address/context and distinguish transport delivery from target execution success: existing ub-transport.cc:2388–2391 queues the TP ACK before dispatch to completed transaction units; ub-transaction.cc:2057–2064 returns no transaction response on unsuccessful execution. A positive TP ACK is therefore insufficient, and failure/timeout handling needs an explicit contract. Rewrite/derive receiver endpoint fields deliberately at replication/delivery boundaries; bare copy retains the wrong peer. ACKs require authenticated/validated target identity; an ACK from B must not advance C/D state. First use individual ACKs (charge reverse traffic); ACK aggregation is a separate extension with explicit aggregation-tree state and loss recovery.

Choose selective-target retries for missing/failed segments, or document all-target retransmission plus target deduplication. Retain payload until all required targets are terminal. Do not equate a transport ACK, any one CQE, or max of observed child timestamps with full logical success unless all intended children are known and terminal. Parent success requires every target success; permanent target failure yields explicit parent failure and documented cancellation/drain of remaining children, never disappearance from membership. Completion is exactly once.

Validation: delay/loss/reorder of data and ACK on one child; duplicate ACK; stale epoch ACK; wrong recipient context; one child NACK/target error; retry exhaustion; group update while old retry exists; a returning old ACK after group-ID reuse; buffer cleanup and target slot reuse. Check first successful child cannot complete parent, no retry corrupts an already completed target, no success is reported with missing children, and terminal outcomes remain visible in the experiment ledger.

Go only after all-target target-execution completion, selective retry/failure, and cleanup are observable and deterministically tested. No-Go on existing unicast `sndUna` reused as a group ACK, missing recipient keys, unchecked failures, or completion based solely on network arrival.

## Phased decision

0. Documentation/provenance: GO for a scoped implementation proposal; UB 2.0.1 §8.6 positively permits functional-layer multicast-style cooperation, but switch multicast fields/semantics and implementation conformance remain UNKNOWN; current module is not multicast-ready by the audited paths.
1. Network model: conditional GO for PoC 1 under fixed membership and explicit bytes/credits; No-Go for performance conclusions until accounting invariants pass.
2. Reliability: establish independent-unicast child oracle, then conditional GO for shared payload only after receiver identity/all-target state redesign; no shortcut through switch clones.
3. Dynamic groups/topology: compare A/B/C under equal frozen memberships, source payload, topology, scheduler, background traffic and CC settings; sweep explicit setup and header costs, not guessed hardware numbers.
4. Performance claims: only after separate correctness gates and measured/simulated dependency-complete results. Report goodput, source bytes, total fabric bytes, bottleneck occupancy, all-target completion, tail latency, control/ACK/retry bytes, setup latency, failure counts, and model limitations. No simulator changes or runs were performed for this design audit.
