# UB switch/network multicast source audit

## Scope and verdict
Read-only audit, 2026-10-18. Source root: the audited native checkout (supply as --native to the evidence script). Git HEAD/base: `d6aa9e242d5a93f5bbd1ad54f39b1620c1b8757b`. No build, simulation, model, Planner, strategies, or runsim changes performed. All line citations below are relative to this root. Audited switch/routing/allocator/queue/port/link/Packet files are unchanged from HEAD. Working-tree differences are function, transaction, datatype, and two test files; they are not multicast implementation. The combined source is identified by the privately retained per-file SHA256 inventories and scoped accepted reconstruction provenance in evidence/provenance.json; base HEAD alone does not identify patched transaction files.

**Implemented:** single-output UB forwarding, VOQs, per-output bounded egress queues, flow-control-aware allocation, per-port serialization and point-to-point propagation, copy-on-write packet copies.

**Structurally feasible, not implemented:** switch-local replication into distinct per-egress normal data paths. A group/output-set resolver and multicast-specific buffer/credit ownership are required. This is not a configuration-only feature.

**Not demonstrated / UNKNOWN:** end-to-end multicast delivery, completion, retry/failure semantics, group lifecycle, measured gain, correctness under parallel simulation. No runtime tests were executed.

Bounded case-insensitive search `multicast|broadcast|replicat` across `src/unified-bus` excluding docs returned zero matches. Positive call-path inspection below confirms the examined forwarding path selects one output; absence of grep matches alone is not a proof about every possible external extension. Generic ns-3 IPv4 multicast/OpenFlow/bridge features were deliberately excluded as evidence of UB support.

Path convention: `model/` below means `src/unified-bus/model/`; bare UB filenames are in that directory unless their protocol subdirectory is named.

## Actual datapath with source anchors

1. **Receive and protocol dispatch.** `src/unified-bus/model/ub-port.cc:UbPort::Receive/DispatchReceive/HandleWithUbSwitch:875–912` records receive then dispatches to `UbSwitch`. `model/ub-switch.cc:SwitchHandlePacket:717–745` classifies UB_CONTROL_FRAME, URMA, LDST, CTP; data receive invokes CBFC restoration before protocol forwarding. `HandleURMADataPacket:751–768`, LDST 774–791, CTP 797–814 distinguish endpoint sink from switch forwarding.
2. **One output, not a fan-out set.** `model/ub-switch.cc:ForwardDataPacket:973–1005` resolves `int outPort`, checks input-space once, sends once. LDST 1011–1040 and CTP 1046–1072 have the same shape. `ResolveURMAOutput:1093–1111` calls `GetOutPort` or `GetOutPortForEndpoint`. `model/protocol/ub-routing-process.cc:GetOutPortInternal:450–532` obtains candidate paths but returns a single `SelectCandidate`; `SelectOutPort:595–608` does likewise. A candidate list is multipath choice, not replication. Compact CTP Entity membership also selects one member port (`ub-switch.cc:ResolveCtpOutput:1153–1188`).
3. **Admission and processing.** `ub-switch.cc:SendPacket:1344–1346` delegates to `ForwardDataPacketAfterAdmission:449–478`, which reserves processing bytes then applies `m_inPortProcessingDelay`. `MoveInPortProcessingToVoq:482–495` pushes to VOQ indexed by outPort, priority, inPort. `FinalizeForwardedPacketEnqueue:498–531` invokes congestion hooks, PFC ingress hooks, then output TriggerTransmit. Existing forwarding explicitly drops on failed ingress admission (`973–1003`).
4. **Buffer accounting.** `model/ub-queue-manager.cc:CheckInPortSpace:144–146` is physical ingress admission. `CheckOutPortSpace:149–155` always returns true: output view of VOQs is accounting, not physical egress capacity. `PushToInPortProcessing:223–236` accounts ingress occupancy and output processing view; `MoveInPortProcessingToVoq:240–261` transfers counters; `PopFromVoq:185–218` releases physical ingress admission and VOQ counters. Do not describe the VOQ output view as an independently bounded egress buffer.
5. **Normal allocation, egress and backpressure.** `model/ub-switch-allocator.cc:FindNextEligibleIngressQueue:450–483` excludes empty/limited/flow-control-limited queues. `ScheduleAllocation:158–177` applies AllocationTime per output. `UbRoundRobinAllocator::AllocateNextPacket:652–710` checks `CanEnqueue` before popping VOQ, enqueues to physical egress, invokes `OnEgressEnqueued`, releases ingress occupancy and upstream credit. DWRR does corresponding work at 935–1030. `model/ub-port.cc:UbEgressQueue::DoEnqueue/CanEnqueue:59–89` provides real byte-bounded egress admission; `EnqueueToEgress:92–110` adds egress counters.
6. **Serialization and propagation.** `ub-port.cc:TriggerTransmit:991–1025` respects BUSY/output failure and drives allocator or dequeue. `DequeuePacket:532–565` sets BUSY, removes egress bytes, then calls `TransmitPacket`. `TransmitPacket:790–842` uses `m_bps.CalculateBytesTxTime(packet->GetSize())`, IFG and packet-rate NOB occupancy and schedules completion. `TransmitComplete:514–529` frees port and triggers next send. `model/ub-link.cc:Attach:95–109` connects exactly two ports; `TransmitStart:174–203` schedules one destination after `txTime + m_delay`. Thus three switch outputs can serialize concurrently on separate links; one output cannot send three copies for free. Directly invoking receiver callbacks, UbLink::TransmitStart, or TransmitPacketDetached is not an acceptable substitute for the normal multicast egress path.

## Most important correctness trap: credits are for arrivals, not clone count

`model/protocol/ub-cbfc.cc:OnIngressReleased:147–156` returns upstream credit for each forwarded packet release, unless its recovery marker says already returned. `OnEgressEnqueued:159–166` consumes downstream credit and attaches output-specific piggyback metadata. `IsFcLimited:109–144` computes required cells as ceil(packetBytes / cellBytes).

Calling existing SendPacket three times after one received packet will reserve three times ingress bytes and ordinarily return three times upstream credit. Calling admission only once while enqueuing three copies also overruns the intended reservation. Returning one credit on the first completed branch without defining buffer ownership may release protection while other copies still occupy memory. These are distinct errors; Packet::Copy does not solve them.

There is an existing **recovery-specific** suppression mechanism: `ub-switch-allocator.cc:MakeAllocatorFlowControlEventContext:52–70` consumes `UbRecoveredCreditTag`; `ub-tag.h:331–336` explicitly scopes it to switch-local recovery and says it does not change wire bytes. This demonstrates a useful separation point, not a ready-made multicast protocol. Reusing this tag indiscriminately would hide semantics and can collide with recovery.

Ingress piggyback credit is already restored and cleared once before forwarding (`ub-cbfc.cc:RestoreDataPacketCredit:455–486`, called by SwitchHandlePacket). Each egress then adds its own piggyback (`TryAttachPiggybackCredit:427–451`). Cloning before receive-side credit processing or cloning a packet after an egress has added its link-specific credit risks duplicate/incorrect credit restoration. Recovery explicitly clears old-link metadata (`ub-switch.cc:ClearOldLinkPiggybackMetadata:1679–1696`).

## Packet::Copy safety and its limits

`src/network/model/packet.cc:Packet::Copy:120–125` constructs a distinct Packet; copy constructor 144–150 copies buffer, byte tags, packet tags, metadata, and separately copies Nix vector. `src/network/model/packet.h:440–449` promises independent observable copies via COW. Header/tag mutation on one copy should not mutate siblings when performed through Packet APIs. `packet.h:800–837` explains COW dirty operations and CPU/memory implications; `buffer.h:39–46`, `packet-tag-list.h:89–111`, `byte-tag-list.h:40–41` document COW backing storage. UB's `CopyPacketView/CopyPacketTransfer` are plain Packet::Copy wrappers (`model/ub-lifecycle.cc:165–176`).

Consequences:
- Header and payload bytes are retained with COW, so a full-packet clone can preserve exact payload while modifying per-receiver destination headers.
- Assigning the same Ptr<Packet> to several output queues is unsafe: output CBFC and tracing mutate the Packet. Each branch needs its own Packet instance.
- COW allocation is not modeled network replication cost; no serialization time or switch copy bandwidth is introduced by calling Copy.
- Copies retain metadata/UID and tags, including flow/transaction identity. Do not use UID alone as a unique branch identity. Copy does not allocate a new receiver transport channel, transaction, ACK state or lifecycle work lease.
- Byte independence does not establish semantic validity of copied endpoint IDs, sequence numbers, correlation tags or receiver completion. Destination rewriting and receiver acceptance must be verified separately.
- Packet tags are simulator metadata, not a substitute for counted on-wire multicast headers. If a protocol introduces bytes, include them before size-based admission, credit calculation and serialization.

## Minimal one-switch A → {B,C,D} design, without bypassing the model

This is a proposal, not current behavior or authorized implementation.

1. Restrict first gate to one switch, three direct receiver links, fixed group membership, one packet/sequence, no failure, single-thread simulation. Recognize an explicit test multicast envelope/group in switch forwarding after incoming link-credit handling. Resolve distinct healthy output ports; disallow input reflection, duplicates and missing members. Freeze resolved membership for this packet.
2. Preserve the existing modeled ingress delay. Create one Packet instance per branch before per-output mutation. Rewrite actual receiver destination where current endpoint sinks require it; preserve payload and explicit logical packet ID with a branch ID. A network-only receive harness must be labeled network-only, not transport-complete.
3. Choose and implement an explicit buffer/replication contract. Suggested first correctness gate: reserve all branch-copy storage atomically at ingress, with one shared arrival-credit owner and branch reference count; enqueue the three branches to existing VOQs, drain independently through normal allocators. Return the original upstream credit exactly once after the last retained branch releases the ingress-owned reservation. Each egress consumes its own downstream credit. This full-copy memory model conservatively charges N packet sizes, but requires properly modeling upstream admission for expansion; ordinary one-packet CBFC credit is insufficient by itself to guarantee room for N copies. A dedicated replication pool/reservation or headroom rule is needed.
4. Alternative shared-payload/pending-mask model charges payload once plus branch descriptors and retains it until all branches commit, but then existing per-branch QueueManager accounting requires explicit changes. It is not achieved by three SendPacket calls. State must include pending branches so retries do not duplicate successful branches.
5. Distinguish **atomic admission** from **atomic egress transmission**. All-or-none admission prevents half-installed fan-out but need not lockstep the outputs. Requiring all outputs to have credit simultaneously creates slowest-receiver coupling and can starve unrelated work; independent branch drain needs explicit pending ownership/one-time release. Both designs need wakeup and teardown paths.
6. Retain normal VOQ → allocator → bounded egress → UbPort::TransmitPacket → UbLink delivery on every branch. Specify extra replication processing time/bandwidth separately, or explicitly mark it unmodeled. Existing InPortProcessingDelay does not prove a realistic multicast engine.

## Required test evidence before claiming support

- One source data packet crosses A→switch; exactly one payload-identical branch reaches each B/C/D, none to A/nonmember; source uplink data bytes counted once and aggregate downlinks counted three times plus real headers.
- Mutate destination, credit flag and trace tag on branch B; verify C/D bytes and tags unchanged. Verify shared logical ID plus distinct branch IDs and no mistaken UID-based deduplication.
- Stall only D by downstream credit or fill its egress; B/C proceed under independent-drain policy; D remains pending, resumes exactly once. Inspect ingress/VOQ/egress counters for nonnegative conservation and final zero.
- Assert upstream credit return equals one original arrival's cells, while each output consumes its own packet's cells. Verify piggyback credit is never reused across neighbors.
- Force insufficient replication storage: all-or-none admission or explicit pending policy, no half-fan-out, no silent credit inflation or memory overcommit. Include two simultaneous fan-outs and unicast interference.
- Check per-output departure timing matches packet size/rate and propagation; verify declared ingress/replication delay. Slow one link and confirm last-receiver completion tracks it.
- Later gate: two switches with a shared trunk (one copy per tree branch), dynamic membership epochs, failed output, cancellation, retries, receiver ACK aggregation and cleanup. None of those follow automatically from the one-switch network test.
