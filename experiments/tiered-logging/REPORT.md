# Three-level logging and full online validation

## Result and scope

Implemented `pair-layer --logLevel=summary|events|debug`, with summary as the default. The EP64 scan runner also defaults to summary. All actual simulation tests described below used the accepted Pair Jetty model and native implementation. No planner, routing, compute, network, WQE/TA segmentation, relay dependency or native protocol code was changed.

Accepted upstream project baseline: `dc17ac7c12d55e7a3444e4d2716aba351a5d75f0` (local equivalent tree `475b2e1c887fc8f79510279dd773d0227668b2f3`). Native commit `2fde39d02920e639f5b200d0c5262a517326deb8`, tree `c27d1faef570e6da9900a71aa0a37180a58dfba8`. Exact built executables and libraries are recorded in `evidence/elf-sha256.txt`.

## Correctness evidence

- Five cases cover small No Balancing, Direct, Chunk Streaming, multi-chunk/multi-TA overlap, and EP64 N256. All run in summary, events and debug, with five additional accepted old-debug reference runs.
- Every simulated metric, phase boundary, per-NPU compute interval, graph fingerprint, final token digest, assignment/load/quota result and packet/TA/WQE count is identical across logging modes. Only the mode label and measured host validation timer are excluded from equality.
- Debug passes the unchanged independent offline oracle. 534 common historical output files match the accepted executable byte for byte.
- The multi-chunk case has 12 group chunks, 36 weight WQEs and 144 weight TAs, 22 application pipeline overlaps and 10 native pipeline overlaps. The test asserts real overlap and segmentation, rather than relying on its scenario name.
- 13 corruption/dependency/completion injections in each mode produce 39 expected application failures, with nonzero exits and explicit FAIL validation. These include actual payload corruption, duplicate completion, early/missing WQE notification, early weight ready, early relay, wrong relay bytes, and early compute. Controlled duplicate tracker notifications remain idempotent; actual duplicate completion is an error.
- Independent preflight reconstructs config/plan/assignments/input and native graph; postflight compares the actual execution graph. Nine input-contract/tamper tests and the retained fixture suite are recorded alongside the source.
- The normal EP64 scan script was exercised at N256 for all three strategies in its default summary mode. All original input hashes, simulator metrics, stage spans and 18 legacy summary fields match the accepted debug scan. No Balancing/direct/chunk layer times remain 56.199264/68.490416/33.176256 microseconds.

`VALIDATION_EQUIVALENCE.md` maps historical offline checks to the online observer, reader, actual-buffer oracle and independent pre/postflight. Summary correctness is per task and per segment; fingerprints and total counters do not replace these checks.

The byte column excludes the identical 2860051-byte input fixture and 40326-byte input-summary provenance metadata, which are recorded separately. The additional validator has a real cost: new debug CPU is about 24% above old debug in this sample. Summary still uses less CPU than old debug because it avoids detailed persistence. No claim is made that validation is free.

## Accounting and retention

Port counters observe actual send/receive notifications. NPU entries are endpoint traffic; the final array entry is switch forwarding. Summing all entries counts hops and control traffic, not unique application packets. Per-stage payload counters are separate. Phase intervals overlap and must not be summed to derive layer time.

Full debug evidence remained local. This delivery contains source, scripts, small JSON/CSV evidence and two representative application timelines, with no raw native trace or payload archive. Debug remains available for case-specific protocol diagnosis.

## Limits

- This validates one representative EP64 size, not a rerun of the full seven-point scaling study.
- Events mode supports the documented key-event set; optional NPU/expert/chunk filters were not added.
- Functional payload validation checks the existing synthetic byte oracle, not numerical tensor computation.
- Online checks retain per-task/per-segment state and buffers; this change does not optimize simulation memory complexity.
- Normal execution should use the runner (or explicit pre/postflight) so that independent config-to-input provenance checks accompany the in-process execution checks.
- Prepared-input replay preserves prior planner CPU timing as provenance. It is not a fresh planner timing measurement.
- Host measurements are observations, not simulated hardware acceleration.
