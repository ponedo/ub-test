# Reproduction and evidence

Use a fresh workspace with ub-test at the reported base plus this module, pinned native d6aa9e242d5a93f5bbd1ad54f39b1620c1b8757b and tools submodule 29009175f1778f76a22d929063c3a0821cb91e56. The accepted capacity/relay setup must already build the original release executor, helper tools and plotting venv. See ../prefill-capacity/README.md and ../multi-npu-relay/README.md. The module deliberately uses /workspace paths to match provenance.

Run `bash experiments/prefill-cpu-profiling/run.sh`. It installs perf under workspace using recorded Debian SHA256s, builds the isolated timer clone, captures flags, runs the declared matrix sequentially, checks full output parity, and runs regressions. It refuses existing raw case directories. The published ledger in a fresh checkout is replaced with a new measurement ledger; retain the published checkout separately for comparison. The original ns3 executable and source are not changed by profiling. The accepted regression build helper may rebuild the identical original app.

The production execution was issued in staged commands (build/capture; 5K; 10K; then 20K/50K; regressions). run.sh assembles those commands; it was not itself rerun end-to-end to avoid redundant performance trials. See raw driver logs, build attempts and stage/resource.json for actual commands and timestamps. The initial timed build failed on a misnamed instrumentation class before compilation; the corrected class is UbTransportChannel. That raw failure is retained, not counted as an experiment result.

The wrapper also runs these postprocessing commands after matrix and regressions: `python3 experiments/prefill-cpu-profiling/conclusions.py`, `/workspace/prefill-profile-venv/bin/python experiments/prefill-cpu-profiling/report.py`, and `python3 experiments/prefill-cpu-profiling/package.py` (after finish.py and symbols.py). Archives are made only after measurements and verified byte-for-byte. See archives/README.md for extraction and split archive reconstruction.

Interpretation: original baseline and original+perf share the same ELF; timer measurements are a different O3 build with g and scopes. Native phase CPU is thread CPU; external stages use process rusage. Perf only samples user-space cpu-clock, not kernel CPU or hardware cycles. Fine scope timings are wall, and inclusive parent/child costs overlap. Original release has function symbols but no debug info, limiting inline-frame attribution. Raw unknown stack frames are retained. No optimization, log removal, cap increase or 100K trial is performed.

Publication exception: raw DWARF stack dumps include inherited credential bytes. publish.py retains originals locally and exports equal-length redacted copies, asserting decoded perf script output is byte-identical. All other raw files remain byte-identical. package.py archives that verified export, not the sensitive original profiles. This is explicitly recorded in evidence/publication-redactions.json.
