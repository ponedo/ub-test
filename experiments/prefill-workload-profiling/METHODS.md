# Sources and measurement policy

This is a reproducible reconstruction of input-length workloads, not an exact reproduction of UltraEP's unpublished serving input pipeline. All revision IDs are in [sources.lock.json](sources.lock.json); actual file/range SHA256 values are in [evidence](evidence/). Public outputs contain lengths, row locations and hashes, never question/answer corpora or tokenizer blobs.

## What the primary sources establish

UltraEP §8.1 names Codeforces, SWE-bench, DAPO-Math-17K, GPQA and OpenScience for STEM, adding LongBench for Mixed. It describes hundreds-to-tens-of-thousands input tokens and Poisson arrivals. Exact revisions, assembly, mixture, sample sizes, filters, truncation and seeds are unspecified. Table 2 uses Qwen3 E128/top-k8/EP64 with two redundant slots per rank; §8.2 describes SGLang routing replay. These facts do not determine a public replay dataset. [Paper v3](https://arxiv.org/html/2606.04101v3#S8.SS1)

The pinned public [UltraEP README](https://github.com/Dots-Infra/UltraEP/blob/94cab099b44fffa99a82fea99e7c12d89cf65e4f/README.md) says its SGLang integration is experimental and will be released later. Its [example instructions](https://github.com/Dots-Infra/UltraEP/blob/94cab099b44fffa99a82fea99e7c12d89cf65e4f/examples/README.md) provide RedPajama training data. We inspected the pinned repository tree and found no six-source serving preprocessing or released full gate trace. File list, relevant line locations and hashes are recorded in `research-audit.json`. This is a finding about that commit, not a claim about private author assets or future releases.

OpenScience selection seed is `20261016 + int(SHA256(config)[:8],16)`, Python `random.sample(range(available_rows), 5000)`, then sorted. Every sampled file/local row is in its CSV; a hash of global selected indices is in the ledger. Parquet footers establish exact available row counts before sampling. HTTP range reads project only input columns, avoiding unused hidden tests or output columns. Full object download is therefore not required for actual measured input access. Range start/end, total object size, ETag and received-byte hashes are retained. Hashes identify downloaded bytes; they are not a claim to hash entire objects that were only projected.

## Tokenizer and context

[Qwen/Qwen3-235B-A22B](https://huggingface.co/Qwen/Qwen3-235B-A22B/tree/8efa61729e24bd65b1d152b5ab5409052aa80e65) is pinned by full revision, not mutable `main`. We download exactly tokenizer.json, tokenizer_config.json, vocab.json, merges.txt and config.json. `tokenizer-manifest.json` records file bytes/hashes, tokenizer class, special-token map and chat-template hash. Library versions are frozen in `requirements.lock.txt`; no model weights or forward pass are used.

Two counts are measured independently for every valid input:

- **raw**: explicit task prompt, `add_special_tokens=False`, no chat wrapper, no truncation.
- **chat**: same prompt as one user message, no system message, `apply_chat_template(tokenize=True, add_generation_prompt=True, enable_thinking=False, truncation=False)`. All delimiters and the fixed assistant prefix, including the template's empty think block, are counted. No generated reasoning/output is included and special tokens are not added again.

Only non-string or empty required inputs are rejected and counted; there is no length filter. A malformed structured source causes a recorded source failure rather than guessing a prompt. Counts are actual tokenizer IDs, not source word counts or character estimates. Chat overhead is measured, not assumed constant across every possible prompt.

The pinned model card documents 32,768 native context and 131,072 with YaRN. Its config has `max_position_embeddings=40960`, `rope_scaling=null`; the card explains that allocation separately. `tokenizer.model_max_length` may be a sentinel. None of these establishes the paper's actual serving `max_model_len`, generation reservation, max-batched-token budget, packing, chunked prefill or admission policy. Our exceedance columns are diagnostics, not applied filters. Context considers **an individual request plus future output**, whereas the batch sum budget concerns multiple requests. Output reservation is unknown, so these input-only diagnostics can understate a configured context failure rate. [Pinned model card](https://huggingface.co/Qwen/Qwen3-235B-A22B/blob/8efa61729e24bd65b1d152b5ab5409052aa80e65/README.md)

## Statistics and synthetic batches

Each series reports N, arithmetic mean, P50/P90/P95/P99, min/max, with NumPy linear-interpolated quantiles. CDF and logarithmic-x histogram plots show both raw and chat counts. LongBench subtasks remain separate. No arbitrary cross-source mixture is synthesized.

For each series and request count 1/2/4/8/16/32, draw 100,000 IID batches **with replacement**. Use NumPy PCG64 with seed `(20261016 + int(SHA256(series + '/' + B)[:16],16)) % 2**63`, and the same sampled indices for raw/chat. Sum input lengths without truncation, packing or padding. Report mean/P50/P90/P99 (also P95/min/max), the exact empirical expected mean `B * mean(length)`, Monte Carlo mean standard error and per-half quantile stability. A 5% half-sample discrepancy is a diagnostic flag, not a proof of convergence or an automatic exclusion. Source sampling uncertainty and distribution shift are not removed by increasing batch repetitions.

Batch sum exceedance and any-individual-request context exceedance are separate columns. These IID batches are **not** Poisson arrivals, a continuous-batching scheduler, Figure 12 RPS/TTFT, a model routing trace or measured network performance.

## Access and licensing observations

These are source metadata observations, not a legal conclusion. No raw corpus is redistributed here. Codeforces' card labels metadata CC-BY-4.0 but prose says “ODC-By 4.0”; retain that ambiguity rather than resolving it silently. DAPO and Qwen metadata say Apache-2.0. GPQA's HF card labels CC-BY-4.0 but is gated; our bytes come from the independently published official GitHub archive. SWE-bench and LongBench HF cards do not provide a uniform license metadata field; upstream code licensing does not automatically license all repository issues or component datasets. LongBench code is MIT; constituent data restrictions still apply. OpenScience states CC-BY-4.0 and additionally notes possible Qwen terms for distributed models improved with the data. This task neither trains nor distributes a model. Consult the pinned upstream cards before other reuse.

## Resolved setup failures and reproducibility limits

The first attempt hit a local duplicate `files` keyword in manifest creation; the next lacked Jinja2 for chat templates. Original errors are retained. The keyword was fixed, Jinja2 pinned, and a chat-template preflight added before dataset work; neither error is a source access failure. The successful ledger/log is the measurement result.

Reproduction requires Python 3.12, HTTPS access to the pinned public sources and sufficient cache space. Network availability is external. Raw corpora and tokenizer files live outside git. Source exceptions are recorded and other sources continue; the generated report lists all missing/failed series. Numerical evidence is deterministic for the pinned artifacts/libraries, while wall-clock timings, HTTP headers, platform and PNG metadata may differ. No end-to-end runtime or RSS scaling prediction is inferred from profiling wall time.
