# Passive reversal diagnostic

The copied application defaults OFF (`--diagnostic=0`). Enable with `--diagnostic=1`. Optional `--diagnosticSource`, `--diagnosticTarget`, and `--diagnosticGroup` select the bounded detailed tail; UINT32_MAX means all. Optional `--diagnosticNodes=3,59,64` limits native aggregates and detailed native parsing to those nodes; leave empty for full aggregation. Include the replication switch and selected destination nodes to preserve complete parent/branch chains. All stage2 transfer times and all-group first-failure reasons are retained regardless of the node filter. They do not change simulated behavior. No interventions are installed.

AllReady retains the exact original short-circuit predicate order. Priority ACK/CNP/retry, empty, and native IsLimited are evaluated only where the original code evaluated them. The native sink captures the result of the already-executed limited branch. No readiness predicate is called to collect evidence.

Outputs:
- `diagnostic-transfers.csv`: every stage-2 transfer, submit, first/last actual native dequeue, last target receive, target completion coverage ready, and sender completion. Sender completion is not WeightReady and must not be charged to its critical path.
- `diagnostic-groups.csv`: actual representative grants and first/last grant times.
- `diagnostic-poll-upper-bounds.csv`: actual_evaluations counts every enabled AllReady evaluation, including repeated identical first failures; observed_spans counts coalesced observation episodes separately. First-failing-member observation spans follow. These are query-held observational upper bounds, NOT continuous waits. They cannot be summed across groups or reasons as causal wall time. Group spans close at original first-send release, not simulation end.
- `diagnostic-native-aggregates.csv`: counts, sums, maxima by metric/node/port/class. Metric 0 VOQ residence; 1 earliest observed selection to successful commit; 2 requested allocation duration; 3 egress wait; 4 serialization; 5 TX bytes; 6 RX bytes; 7 explicit TX delay. 1000+ denotes unmatched end counts. 200+ native reason enum is observed limited-query count. Classes: 0 stage2 weight, 1 ACK/transaction response, 2 other. Packet durations overlap and are NOT an additive wall-time decomposition.
- `diagnostic-weight-phase-cohorts.csv`: same native metrics restricted by the event phase. VOQ/selection/egress durations are full residence for end events occurring during the weight phase; TX/grant service and byte counts are full values for events starting during the weight phase. These are explicitly labeled cohorts, NOT clipped occupancy. A residence can start before the phase; a service can extend beyond phase end. Keep these separate from exact occupancy partitions and do not call their sums causal wait.
- `diagnostic-port-partition.csv`: exact disjoint measured intervals from weights_start through weights_end per observed node/port admitted by diagnosticNodes (independent of detailed-tail source filtering): TX-busy union (native completion duration), allocator pending excluding TX, and uncovered idle. This accounts for overlapping TX/allocation once. Uncovered idle is not automatically any particular eligibility cause.
- `diagnostic-source-last-send-partition.csv`: the same partition ending at the selected source's last native stage2 packet dequeue, before the final packet necessarily finishes physical transmission.
- `diagnostic-weight-tail.csv`: selected event ring frozen at weights_end, preserving the final weight dependency instead of allowing subsequent ACK/sender completion traffic to overwrite it.
- `diagnostic-tail.csv`: selected event ring at run end. Envelope physical events with no task tag are retained at selected nodes by UID; EnvelopeDecode supplies group/sequence and NativeBranch supplies parent UID. Native kind numbers follow ub-reversal-diagnostic.h; application 100 submit,101 native send,102 target receive,103 receiver ready,104 sender complete,105 physical WeightReady,106 AllReady reason transition,107 actual grant.

Each ring holds 65,536 fixed-size records and reports intentional overwrites. Maps have hard caps: 65,536 stage2 transfers; 131,072 outstanding interval/correlation/aggregate keys per bounded map, 1,024 groups, 4,096 activity ports. A cap failure aborts the run and marks evidence incomplete; it never silently drops aggregates. Estimated recorder storage at all independent caps is below 128 MiB using conservative per-node bookkeeping estimates; normal simulator/application payload memory is not part of that recorder budget. There is no payload storage in the recorder and no per-packet file writes. CSV files are generated once after the run. The existing simulator/application payload memory is independent of this instrumentation.

`diagnostic-status.json.incomplete` must be false and the ordinary simulation validation must PASS. Tail overwrites alone do not invalidate aggregate evidence, but a missing final causal packet in the frozen ring prevents claiming a complete packet-chain explanation. `open_interval_keys` exposes unmatched starts and must be investigated, not automatically treated as continuous wait. Port partition rows must sum exactly to their stated interval. No counter or poll upper bound can substitute for actual critical-path intervals; report any unexplained residual explicitly.

## FIFO observer repair

VOQ and egress residence match the actual native FIFO sequence per queue, never a unique packet UID assumption. Multiple fragments can share a UID concurrently. Each push records its own timestamp, UID and class; each pop consumes exactly the front observer record. Native VOQ post-operation depth, UID order and nonnegative time are validated. Unmatched/order/depth errors abort observation with incomplete evidence; open FIFO records at finalization also mark incomplete. Status fields queue_observations_open, queue_unmatched, queue_order_errors and queue_depth_errors must all be zero. queue_observations_peak records peak outstanding observation records. Limits are 131072 total FIFO records and 8192 nonempty observed queues.

Activity rows cannot be created or changed after weights_end. Every in-phase GrantStart and TxStart on a selected node is retained in the bounded tail, including traffic outside the critical task filter; these resource starts support interval reconstruction within the retained ring only. The exact online partition remains authoritative beyond the ring's retained window.

observer-fifo-test.cc is a synthetic observer-only test (no Simulator::Run or scheduled/model operations) covering duplicate fragment UIDs in one VOQ/egress queue and independent queues, exact residence sums, zero unmatched/open state, fail-closed bad observations, phase boundary, and resource-start retention.

Allocation outcome observation: metrics8/9/10 respectively record rejected, no-ingress, and successfully committed allocation counts and actual elapsed picoseconds from the preceding physical-port GrantStart event. No duration is hardcoded. They are end-in-weight-phase full-duration cohorts in the cohort file, not additional occupancy to add to the partition. GrantRejected/GrantNoIngress are native outcomes of existing branches, with no extra eligibility probes. Missing/overwritten starts or starts still open at finalization mark incomplete evidence; grant_outcomes_unmatched, grant_start_overwrites, and grant_starts_open must be zero. Selected-node outcome events are retained in-phase in the bounded tail.
